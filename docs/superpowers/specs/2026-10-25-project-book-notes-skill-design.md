# 项目书籍与文章解读技能设计

## 意图

为当前仓库增加一个仅在书籍或独立文章解读任务中自动触发的项目级技能。它在调用合适的内容分析能力完成解读后，将结果归档为 Markdown，并把本次解读产物独立提交、推送到当前分支的远程。

## 目标

- 仅对拆书、章节解读、读书笔记、核心观点分析或独立文章解读任务触发。
- 新书自动创建以书名命名的根目录；已有书籍复用原目录。
- 独立文章统一保存到仓库根目录的 `article/`；书籍章节仍保存到对应书名目录。
- 整本书、章节和专题结果采用可读且稳定的 Markdown 文件名。
- 每次只提交本次生成或修改的书籍文档，不夹带无关工作区改动。
- 写入后验证文件，再提交并推送；失败时保留本地成果并说明失败环节。

## 非目标

- 不在 Git 维护、代码开发或其他非内容解读任务中触发。
- 不重新定义 `book-reader` 的内容分析方法。
- 不擅自修改或覆盖已有读书文档；文件名冲突时更新明确指定的文件，否则采用不冲突的新文件名。

## 方案

采用仓库级自包含技能 `.agents/skills/managing-reading-notes/SKILL.md`。相比 `AGENTS.md`，它能按任务语义触发；相比额外脚本，它更适合需要理解书名、文章标题、章节和主题的判断型流程，也减少维护成本。

## 工作流

1. 确认任务属于书籍或独立文章解读。书籍任务使用 `book-reader`；文章任务根据原文完成结构化深度解读。
2. 区分独立文章与书籍章节：有明确书名及章节归属的内容视为章节；没有书籍归属的内容视为独立文章。不能可靠判断时先询问用户。
3. 书籍任务从请求或材料中确定规范书名，并在仓库根目录定位或创建书名目录。独立文章统一定位到根目录的 `article/`，不存在时创建。
4. 保存 Markdown：整书使用 `书名-深度拆解.md`，章节使用 `第X章-章节标题-深度拆解.md`，书籍专题使用简洁的主题名，独立文章使用 `文章标题-深度解读.md`。
5. 检查文件路径、扩展名、非空内容以及 Git 差异。
6. 仅暂存该任务创建或修改的书籍文件；提交信息概括书名与内容范围。
7. 推送当前分支到其已配置的上游。没有上游、认证失败或远程拒绝时停止重试，保留本地提交并报告。

## 约束

- 自动选择技能保持开启。
- Git 操作不得包含无关文件。
- 不使用强制推送，不改写历史，不删除用户文件。
- 技能本身作为仓库内容提交，以便以后在该项目中新建的任务都能发现它。
- `article/` 只存放没有书籍章节归属的独立文章解读，不存放书籍章节。
