# 管理解读笔记

## 核心原则

完成内容解读，也完成可追溯归档：先判断材料归属，再生成 Markdown，只提交并推送本次解读产物。

## 解读与分类

- **书籍、章节、书中专题：** **REQUIRED SUB-SKILL:** 使用 `book-reader` 完成深度解读。
- **独立文章：** 根据用户提供的原文或链接内容做结构化深度解读。文章提及一本书，不等于它是该书章节。
- 有明确书名及章节归属时按书籍内容处理；没有书籍章节归属时按独立文章处理。无法可靠判断标题或归属时，先询问用户。

## 保存位置与命名

| 类型 | 目录 | 文件名 |
|---|---|---|
| 整本书 | 仓库根目录下的 `<书名>/` | `<书名>-深度拆解.md` |
| 书籍章节 | `<书名>/` | `第X章-<章节标题>-深度拆解.md` |
| 书中专题 | `<书名>/` | `<专题名称>.md` |
| 独立文章 | 仓库根目录下的 `article/` | `<文章标题>-深度解读.md` |

复用已有的等价书名目录，不因书名号、空格或副标题差异重复建目录。文件名移除 `/`、`:` 等路径分隔字符，并确保扩展名只有一个 `.md`。

只有用户明确要求更新某个已有文件时才覆盖它。其他同名冲突使用能区分内容的标题或日期后缀创建新文件。

## 完成与验证

1. 在写入前查看 `git status --short`，记住已有改动和暂存内容。
2. 保存完整解读，不把聊天中的简略摘要当作最终文件。
3. 检查目标文件位于正确目录、内容非空、扩展名正确，并用精确路径查看差异和 `git diff --check`。
4. 只用精确路径暂存本次创建或修改的解读文件；不得使用 `git add .` 或 `git add -A`。
5. 检查暂存清单。若包含任务开始前已有的文件或任何无关改动，停止自动提交并向用户报告，不改变那些改动的暂存状态。
6. 提交信息包含书名或文章标题及解读范围。提交后再次检查工作区，确认无关改动未进入提交。
7. 确认当前分支已有上游后执行普通 `git push`。不得强制推送、改写历史或自动创建上游。

推送只尝试一次。上游缺失、认证失败或远程拒绝时，保留本地文件和提交，说明失败环节与用户可采取的下一步。

## 常见错误

- 将独立文章放进某本书目录：只有明确章节归属才这样做。
- 为已有书籍创建近似名称的新目录：先检查并复用现有目录。
- 提交整个工作区：始终按本次产物的精确路径暂存并复核。
- 为完成自动化而强推：推送失败即停止，保留可恢复状态。
