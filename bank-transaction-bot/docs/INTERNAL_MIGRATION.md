# 内部定义补齐与迁移手册

本文件是集中补充说明。2026-11-22 已完成四层配置拆分，结构与修改示例见 [四层配置指南](FOUR_LAYER_DESIGN.md)。所有默认金额、时区、地区、策略和示例均为模拟，不代表银行政策。可运行演示不等于已完成生产银行集成。

## 1. 已实现的闭环与范围

网页选择授权范围内的模拟候选交易 → 识别意图 → 模拟适配器取证 → 本体类图提供原因分类和指引匹配 → 业务服务确定诊断 → 披露白名单 → 网页说明和证据面板。

已覆盖 Entity/Card/Account/Product 四层、七类原因、六类限额；允许多项发现，保留记录主因、记录次因、可能阻碍和当前状态。确定性单独采用 CONFIRMED/INFERRED/UNKNOWN/CONFLICTED。

有意保留的边界：演示只使用规范化的控制评估结果，不从原始 MCC/国家/开关字段自行重建银行完整授权引擎。配置不是命中，命中不一定是实际拒绝主因。默认不做支付、不解冻、不改限额、不创建真实工单。

## 3. 核心对象与字段合同

### 3.1 本体目录

`config/ontology.json` 是默认运行时的单一目录源：

- `classes`：类型父类、原因类别；运行时检查类不存在和继承环。
- `reason_categories`：七类原因；Product 层级和 PRODUCT_CONFIGURATION 类别独立。
- `limit_types`：六类限额的业务名称、周期及演示范围。
- `actions`：仅保存指引ID与适用概念关系。中文标签、说明在 templates/zh-CN.json；不是授权过的可执行动作。

`tools/export_ontology.py` 从目录生成 `ontology/card-decline.ttl`。TTL 中 defaultReasonCategory 是注解，不宣称由 OWL 自动继承；运行时分类由显式父类遍历实现。SHACL 起步约束在 `ontology/shapes.ttl`，不在默认请求路径执行，也未作为完整 OWL 一致性验证。

迁入 RDF 环境时，需要把规范化实例转换成 RDF，分别验证实例/shape，再选择 RDF 库或推理机。不能只加载 schema 然后把“校验通过”当作所有生产数据正确。

### 3.2 银行适配器

首先替换 `app/adapters.py` 的 `MockBankAdapter`，保留服务分层。当前接口：

```python
list_attempts(principal) -> list[dict]
get_attempt(attempt_id, principal) -> dict
```

**重要：当前 principal 固定为 demo-customer，仅适合模拟。** 迁移时必须从服务端可信身份会话取得，并在每次查询中由数据源校验对象归属；不要采信浏览器或模型给出的客户 ID。相应修改 service 的请求上下文，而非仅把 config/runtime.json 中用户名换成真实用户。

建议内部拆为授权候选查询、授权决策查询、历史控制评估、当前控制查询、当前限额业务计算。保持业务接口的已有语义，不在 Prompt 中另写规则引擎。

最小交易字段：

| 字段 | 语义 |
|---|---|
| id / owner | 授权后可引用的交易标识及所属主体 |
| occurred_at | 有时区的交易发生时间 |
| retrieved_at | 本次取得证据的时间；生产由服务端实际采集 |
| amount / currency | 十进制字符串和币种，不用浮点 |
| decision_origin / decision | 真正决策来源及结果，区分超时与拒绝 |
| historical_snapshot | 历史快照是否可用，不可用不是 false 命中 |
| controls[] | 已规范化的控制评估或候选控制 |

每个控制至少包含：id、type、level、target_ref、evaluation、primary、effective_at_transaction、current_active、evidence_refs、source_system、rule_version。生产中 current_active 还需独立当前证据及有效时间，不能只给无来源布尔值。示例当前状态为预置模拟事实。

`evaluation`：PASS / FAIL / SKIPPED / ERROR / UNKNOWN。`primary` 必须来自授权记录或可信业务工具，不能按层级或最小限额自行排序认定。单个限额快照不证明它参与实际拒绝。

缺失字段在真实适配器应显式转为缺失/错误状态，不要用成功的空记录掩盖超时、无权限或无历史。当前映射层已对白名单字段、必填项、枚举、金额及部分布尔/证据类型做校验；生产仍需补齐完整接口schema、错误分类和历史/当前证据合同，不能把任意原始响应直接交给service。

### 3.3 限额合同

历史 `limit` 和当前 `current_limit` 分开。包括 configured/effective/used/period/currency/window_start/window_end/timezone；六个完整限额案例提供当前快照，其余缺失时返回 UNKNOWN。

当前快照必须有自身 evidence_refs。配置层级和 aggregation_key 独立；如产品定义“每卡每日”，累计键应为卡，而不是全产品。

限额事实由 diagnosis.py 构造，确定性与冲突处理由 rules/diagnosis.json 决策表执行。演示只支持 SINGLE 与 DAILY、同币种十进制加法；24 位有效数字、指数绝对值不超过 12。等于上限不判超出。负剩余保留原值；缺失累计用量不按零。单笔限额不显示日剩余额度。

生产优先直接使用银行业务工具返回的有效额度、已用和剩余，不在此处重算占用、汇兑和冲正；将 evaluate_limit 替换或封装为统一业务计算结果。日剩余不是全部约束下的最大可交易金额。并发查询结果也不预留额度。

## 4. AI 的接入与迁移

当前 AI 接口只做意图识别，没有工具自主执行或自由生成诊断。模型请求不含原始银行数据；输出必须为允许枚举。网络不可用时回退，网页区分本地/LLM/回退。

如内部已有 deepagent，可将本工程诊断服务作为受控工具，并把现有 skill 的流程放入 agent 编排，不重复开发业务判断。建议工具合同：

- find_authorized_attempts：限定主体与时间范围，返回脱敏候选。
- investigate_decline：返回已过滤的发现、确定性、证据引用与指引。
- get_current_limits：按交易范围返回业务工具计算结果。
- get_current_controls：返回当前有效状态与来源。

未来若采用模型生成自然语言，输入应为**已经过滤的客户视图**，并做输出校验；不得让模型先看到风控内部依据再靠提示词保密。生产需 DLP、数据驻留与模型网关策略，当前长数字替换不是完整敏感数据识别。

## 5. 解释、披露与动作

- CONFIRMED：匹配对象/时间的直接证据支持；当前状态确认不等于历史因果确认。
- INFERRED：间接支持，明确“可能/无法确认历史原因”。
- UNKNOWN：缺少关键证据、查询失败或没有所需能力。
- CONFLICTED：对齐对象、时间、币种后仍然冲突，需保留并升级。

当前风险字段使用白名单构建结果，原始 score/threshold/rule 不返回。其他来源标识、控制类型和层级目前也会出现在调试面板，**并未实现完整的客户披露政策**。正式客户版需分离客服内部视图和客户视图；按身份、市场、产品实施字段级授权，隐藏敏感控制存在性和标识。不要将“隐藏”实现成删除内部证据。

默认的通用指引不带银行电话或链接，避免杜撰。用内部审核过的渠道替换。所有动作均 GUIDANCE / NOT_EXECUTED；没有真实工单或写操作。

未来启用写操作必须在银行工具层实现：具体对象与参数确认、强认证、资格检查、幂等、状态查询、审计。修改成功与下次交易成功分开描述。不能只把 allow_writes 改成 true；当前字段不创建写接口。

## 6. 按顺序迁移

1. 保留 MOCK，先运行全部测试与演示案例，确认环境可用。
2. 完成 D01–D16；明确范围、版本与例外；追加内部实例测试。
3. 完成服务端身份、租户隔离、授权范围，再接只读测试数据源。
4. 新建 BankAdapter，规范化数据；开发期保留 MockAdapter 对照。
5. 将适用性、优先和限额计算接入现有业务工具；补齐错误和超时合同。
6. 固定版本并回放脱敏历史案例，核对主因与人工答案；覆盖跨日、换卡、重复尝试、不同币种和并发。
7. 建立客户/内部视图和披露审批；替换通用指引。
8. 选择批准的模型网关，验证意图与回退；若保留本地模式，应明确其能力限制。
9. 用内部生产框架/反向代理替换标准库 HTTP 服务。当前只绑定 localhost，没有生产认证、TLS、限流、持久化会话或完整观测。
10. 分阶段灰度，只读先行；写操作作为单独项目验收。

## 7. 上线前必须验证

- 服务端校验主体；换用户、换卡、伪造交易 ID 无越权；无数据存在性泄漏。
- 当前/历史证据分离；跨日/时区对齐；未执行不是通过。
- 所有六类限额与四层组合，明确共享额度和取现重叠；币种不一致不硬算。
- 记录主因、多原因和短路评估；缺失和冲突不输出确定结论。
- 控制来源与动作权限一致，法律或银行锁不能按客户锁处理。
- 风控敏感字段及控制存在性按政策处理；银行数据不被未批准的模型网关接收。
- 使用历史回放评估原因准确率、无依据断言率、披露违规率及处理有效率。
- 不把标准库 demo HTTP 服务直接暴露外网，不把 MOCK 冒充 LIVE。
